# 4.2 Implementasi Sistem

## Struktur proyek

Aplikasi mengikuti pemisahan tiga lapis: `models.py` (SQL), `services.py`
(validasi dan aturan bisnis), dan `routes.py` (rute HTTP tipis). `app.py`
membuat aplikasi, mendaftarkan CSRF, header keamanan, dan memuat `versi.py`.
Templat Jinja2 berada di `templates/` dengan satu `base.html` dan satu
`static/style.css`.

## Cuplikan kode terpilih

**Pemeriksaan peran (routes.py)** — mengapa penting: penegakan akses dilakukan
di sisi server, bukan hanya menyembunyikan tombol.

```python
def peran_diperlukan(*peran):
    def decorator(fungsi):
        @wraps(fungsi)
        def bungkus(*args, **kwargs):
            if g.pengguna is None:
                return redirect(url_for("main.login", next=...))
            if g.pengguna["peran"] not in peran:
                abort(403)
            return fungsi(*args, **kwargs)
        return bungkus
    return decorator
```

**SQL berparameter (models.py)** — seluruh query memakai placeholder `?`,
termasuk pencarian yang sudah menetralkan wildcard.

```python
def get_all_kamar(kata_kunci=""):
    pola = f"%{_escape_like(kata_kunci.strip())}%"

        "SELECT ... FROM kamar AS k WHERE k.nomor_kamar LIKE ? ESCAPE '\\'",
```

## Ringkasan siklus prompt representatif

Tiga siklus dari `jurnal-vibe-coding.md` yang paling mengajarkan:

1. **D-01 (Ubah):** AI mengusulkan mengganti seluruh blok `try/except`
   tanggal beserta pesannya. Saya menolak perubahan pesan karena dua berkas uji
   lama mencocokkan teks lama. Pelajaran: perbaikan sekecil mungkin.
2. **CSRF (Ubah):** AI menambahkan token pada form data, tetapi melewatkan
   form logout pada `base.html`. Pemeriksaan manual dengan mencari semua
   `method="POST"` menemukan 9 form, bukan 8. Pelajaran: pencarian menyeluruh
   mengalahkan daftar yang diasumsikan.
3. **Rencana UAT (Tolak):** AI mengusulkan tanggal UAT rekaan agar tampak
   lengkap. Saya menolak: jadwal harus disepakati klien, bukan dibuat-buat.
   Pelajaran: membedakan "direncanakan" dan "disetujui".
