1. Lingkungan Deployment dan Alasan

Lingkungan yang disepakati: komputer toko (jaringan lokal) — pengguna di satu lokasi, tanpa biaya hosting. Komputer server harus menyala; firewall mengizinkan port 8000; cadangan rutin disimpan di tempat terpisah. Server pengembangan Flask (python app.py) tidak dipakai untuk produksi; digunakan Waitress (waitress-serve --listen=127.0.0.1:8000 app:app).

Cookie Secure: COOKIE_SECURE=0 dipakai pada jaringan tertutup tanpa HTTPS agar sesi tetap tersimpan; bila aplikasi dapat diakses lewat internet, harus HTTPS dengan COOKIE_SECURE=1.

3. Bukti Aplikasi Berjalan (Waitress, mode produksi)

Perintah: waitress-serve --listen=127.0.0.1:8000 app:app dengan APP_ENV=production, SECRET_KEY dari lingkungan, COOKIE_SECURE=0 (jaringan tertutup). Hasil: halaman login tampil, login pemilik dan kasir berhasil, daftar kamar (A-01, B-01) tampil, footer menampilkan v1.0.0. Tanpa SECRET_KEY, aplikasi menolak start dengan RuntimeError: FLASK_SECRET_KEY/SECRET_KEY wajib diatur pada lingkungan produksi.

4. Bukti Cadangan dan Pemulihan

python cadangkan.py menghasilkan cadangan/kontrakan-YYYYMMDD-HHMMSS.db. Latihan pemulihan: satu kamar dihapus, berkas cadangan disalin menimpa basis data, kamar kembali (2 kamar). Prosedur cadangan dan pemulihan tertulis di README (frekuensi, lokasi simpan, siapa bertanggung jawab).

10. Jawaban Pertanyaan Evaluasi

  1. Rahasia dan basis data tidak boleh di Git karena bocor ke publik dan ada di riwayat. Bila terlanjur ter-commit: cabut dan ganti rahasia, hapus berkas, dan perlakukan isinya sebagai bocor.
  2. python app.py tidak untuk produksi karena server pengembangan Flask tidak menangani beban dan keamanan. Server WSGI (Waitress) menangani banyak permintaan dan mode produksi.
  3. Semantic Versioning: MAJOR (tidak kompatibel), MINOR (fitur baru kompatibel), PATCH (perbaikan cacat). PATCH naik untuk perbaikan cacat; MINOR untuk fitur baru.
  4. README vs manual pengguna: README untuk pengembang/teknisi yang memasang (kriteria: pihak lain berhasil memasang); manual untuk pemilik/kasir (kriteria: menyelesaikan tugas tanpa bertanya).
  5. Triase umpan balik: cacat (menyimpang PRD → perbaiki + uji), kesulitan penggunaan (perbaiki teks/manual), permintaan perubahan (calon v1.1). Lingkup 1.0.0 tidak diubah mendadak tanpa persetujuan klien dan dosen.
