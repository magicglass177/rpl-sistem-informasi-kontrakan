@app.before_request
def periksa_csrf():
    if request.method != "POST":
        return
    dikirim = request.form.get("csrf_token", "").encode()
    asli = session.get("csrf_token", "").encode()
    if not asli or not secrets.compare_digest(dikirim, asli):
        app.logger.warning("CSRF gagal path=%r ip=%s", request.path, request.remote_addr)
        abort(400)

11. Jawaban Pertanyaan Evaluasi

  1. Lima sudut pandang tinjauan: kesesuaian kebutuhan (apakah kriteria terpenuhi?), kebenaran (kasus pinggir?), keamanan (SQL/akses/rahasia?), keterbacaan (nama & duplikasi?), dependensi/konfigurasi (paket dikenal, debug/kunci/cookie aman?). Semua diterapkan pada kasus dan proyek sendiri.
  2. f-string SQL berbahaya karena masukan pengguna menjadi bagian perintah, mis. pemilik' -- menonaktifkan pemeriksaan kata sandi. Perbaikan: SQL berparameter WHERE username = ?. Bukti: uji injeksi kini menghasilkan 401.
  3. CSRF adalah pemaksaan permintaan oleh situs lain memakai cookie korban. Hapus lewat GET dapat dipicu tautan/gambar; form tanpa token dapat dikirim pihak ketiga. Perbaikan: POST + token per sesi + pengecekan server.
  4. Paket fiktif muncul karena AI mengarang nama mirip paket nyata. Sebelum memasang: cek nama persis di PyPI, pembuat, tanggal rilis, jumlah rilis, dan tautan repositori; bila ragu, jangan pasang.
  5. Komentar konstruktif menunjukkan lokasi, alasan, usulan, dan membedakan wajib/saran. Buruk: "Kode ini ceroboh." Baik: "Query di baris 41 menyambung nama ke SQL. Usul: pakai ? dan tuple parameter; lihat baris 28 sebagai contoh yang benar."
